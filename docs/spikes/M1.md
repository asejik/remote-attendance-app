# M1 Spike: Offline clock-in on a real phone

**Question:** can a worker clock in with no network, close the app, restart the phone, and have every record upload by itself once the network returns? We test both the **web app** (installed from Chrome) and the **Android app** (APK built in the cloud).

**Test phone:** itel P55 5G, Android 13.
**Status:** built, waiting for the phone test. The results table below is still empty.

## What was built for the spike

| Piece | Purpose |
|---|---|
| Service worker (vite-plugin-pwa) | The web app opens offline and the face models (0.9 MB) are stored on the phone |
| `navigator.storage.persist()` | Asks the browser not to clear stored clock-ins |
| Cached site list | The site picker works offline (it showed nothing offline before) |
| Automatic upload | Runs when the network returns, when the app comes back to the foreground, and every 5 minutes. Only one upload runs at a time. |
| `/diagnostics` screen | Shows the readings this test needs |
| Android project (Capacitor 8.5, min Android 7.0) | Camera and location permissions. Cloud backup of app data is turned off, so face photos never go to Google Drive. |
| GitHub Actions APK build | No Android Studio needed. The APK is attached to the `android-test` pre-release. |

**Automated check (passes):** the web app reloads with the network cut and still opens, and the face models load from the phone's storage (`tests/e2e/offline.spec.ts`).

## Test script (about 15 minutes per app)

Use a staff test account. Do the test **outdoors or near a window** so GPS can get a fix.

### Part A: Web app (Vercel preview link of the `rebuild` branch)
1. On the phone, open the preview link in **Chrome** and log in as staff.
2. Chrome menu (⋮) → **Add to Home screen / Install app**. From now on, open it from the home-screen icon.
3. Open the app → scroll down → **Device diagnostics**. Write down the readings for the rows in the results table (Offline app, Storage protected, storage available). If *Storage protected* says NO, tap **Protect storage** and note the new value.
4. Tap **Test face model load** and **Test GPS fix**. Write down both results.
5. Turn on **Airplane mode**. Swipe the app away completely, then reopen it from the home-screen icon. *Does it open? Are you still logged in?*
6. Select a site and **clock in** (smile → site photo). Then **clock out**, then **clock in** again (3 records). *Did each one save? Note anything odd.*
7. Diagnostics: *Waiting to upload* should be **3**. Note the face and site photo sizes.
8. **Restart the phone**, still in airplane mode. Open the app → Diagnostics: *Waiting to upload* should still be **3**.
9. Turn **Airplane mode off**. Keep the app open for 2 minutes. Diagnostics: *Waiting to upload* should be **0**, and *Last upload run* should say **3 sent**.
10. (Optional) Log in to the admin page on a laptop and check that the 3 records appear with photos.

### Part B: Android app (APK)
1. On the phone, open **github.com/asejik/remote-attendance-app/releases/tag/android-test** and download `attendance-test.apk`.
2. Open the downloaded file. Allow **Install unknown apps** for Chrome when asked, then install.
3. Open **Attendance**, allow **camera** and **location** when asked, and log in as staff.
4. Repeat Part A steps 3–10. *Offline app* will say "not needed (native)".

## Fake-GPS detection (research, not built)

- Android marks fake locations: `Location.isMock()` (Android 12+) and the older `isFromMockProvider()`. Neither is exposed by the browser or the official Capacitor geolocation plugin, so **the web app can't detect fake GPS. The Android app can.**
- `@capgo/capacitor-mock-location-detector` combines several checks (the mock flag, developer options, known spoofing apps, emulator signs) and returns a score. It still needs to be reviewed and tested on the itel phone.
- Detection on the phone can be bypassed by determined users. Treat it as **a flag for admin review, never proof.** That matches the plan's "flag, don't block" approach.
- Recommendation: add it in the "Next" phase as a flag on Android clock-ins (`mock_location`).

Sources: [Capgo mock location detector docs](https://capgo.app/docs/plugins/mock-location-detector/), [Android setup](https://capgo.app/docs/plugins/mock-location-detector/android/).

## Known limits found while building
- **Session expiry offline:** the app keeps the stored login when offline. Whether it survives several days offline (expired session) is to be observed in step 5. The rebuilt sync engine (M4) handles this explicitly.
- **Android app icon** is still the default Capacitor icon. The proper icon comes with the product name.
- The diagnostics screen is available to any logged-in user. It shows only this device's own counts. **Remove or restrict it before launch.**
